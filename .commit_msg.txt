fix: 5 credential-vault bugs found via scenario tracing

Bug 1 — Multi-tenant domain collision (credentials.py):
Workday/iCIMS/Greenhouse/Lever share second-level domains across
tenants. crowdstrike.wd5.myworkdayjobs.com and
autodesk.wd5.myworkdayjobs.com both resolved to wd5.myworkdayjobs.com
— sharing one vault entry. Each company is a separate account. Now
uses full hostname for multi-tenant SLDs (Workday, iCIMS, Greenhouse,
Lever, Comeet, Jobvite, MyWorkdaySite). Registered domain + 1
subdomain for corporate sites (careers.company.com).

Bug 2 — All-passwords-failed returned True (fill.py):
Login exhausted all candidates, printed failure, but returned True
so fill proceeded to interact with the login page. Now returns False
and emits login_failed status + next=login so the pipeline stops.

Bug 3 — Uncertain login treated as failure, next password tried
(fill.py):
On slow SPAs, the sign-in form stays visible > 5s after a correct
submit. _login_succeeded returned False so next password was tried
so double-submit with wrong password so potential account lockout.
Now uses a three-way _login_check (yes/no/uncertain). On uncertain,
waits 5 more seconds and re-checks once. If still uncertain after
extended wait, assumes success (conservative — don't risk lockout).

Bug 4 — Account creation saved creds without verifying (fill.py):
save_creds ran immediately after submit.click() + sleep(5). A
validation error (password too weak, email mismatch, unchecked box)
would save a bogus password to the vault. Now _check_account_created
verifies the form disappeared and no error text is present before
saving. On failure, emits login_required with instructions.

Bug 5 — Workday Create Account checkbox never checked (fill.py):
Workday's Create Account form has
data-automation-id=createAccountCheckbox ("I understand...") that
must be checked before submit. The fill code never checked it so
validation error so account creation always failed. Now checks the
checkbox before filling name fields.

Bug 6 — Password index in log used list.index() (fill.py):
creds['passwords'].index(tried_pw) returns first match — wrong
index if duplicates exist. Now uses enumerate() index.
